# Listary 文件搜索优先级设置线索

用户提供了本机 Listary“文件搜索 → 优先级”设置截图，作为行为研究资料。本次仅记录和分析，不改变 QBox 的匹配、排序、过滤或索引规则。大幅修改仍须先给出方案及前后对照，获得用户确认。

原图保存在 `references/listary-priority-2026-11-14.png`。截图中的“高”和“不索引”区域可见为空。

## 截图可直接确认

“正常”列出了：

- `%USERPROFILE%\AppData\Roaming\Microsoft\Internet Explorer`
- `%USERPROFILE%\AppData\Roaming\Microsoft\Windows`
- `%ProgramData%\Microsoft\Windows\Start Menu`

“不常用文件”列出了：

- “默认不展示系统及隐藏文件的搜索结果”这一过滤描述。
- `%SystemDrive%\Windows.old`、`%SystemDrive%\$WINDOWS.~BT`、`%SystemDrive%\$Windows.~WS`。
- `%ProgramData%`、`%SystemRoot%`、`%USERPROFILE%\AppData`、`%ProgramW6432%`、`%ProgramFiles(x86)%`。
- 名称模式 `^\.`、`^~`、`^[^.]+$`、`^node_modules$`、`^\$`。

这确认设置包含按路径及名称/属性条件进行分级的机制，不只依赖名称匹配分数。正常路径与不常用父路径存在重叠，尤其是开始菜单位于 ProgramData 内、用户开始菜单位于 AppData 内。

## 本地配置的只读核对

本机 `Preferences.json` 的 `DiskSearch` 对象分别保存 `FileNamePriority`、`FolderPriority` 和 `SearchFilter`。这三个对象当前均为 `Deletions`、`Insertions`、`Moves`、`Updates` 四个空列表。这里只提取相关字段，没有读取搜索历史、修改配置或完整复制个人配置到项目。

配置结构证实名称优先级、目录优先级、搜索过滤是分开的设置对象。空差量与截图展示的规则共同提示默认规则可能来自程序或默认配置；这仍是待验证的来源判断，不能把空差量误解为没有生效规则。

主程序哈希仍为 `f728593f86597b95d9ee79c03f8e7d313ca4c79a4bab8cf31f3768febeb8063f`。进一步只读定位到与截图一致的字面量：`^node_modules$` 位于 `0x1427c4494` 和 `0x14280ce44`，`Windows.old` 位于 `0x1427c4205` 和 `0x14280cbb6`。这些地址可用于后续查找默认规则及配置构造；当前仅定位字符串，尚未证明对应的执行路径或排序键含义。

## 对现有差距的帮助

QBox 当前结果包含较多 Windows、ProgramData、AppData、安装目录及依赖目录中的同名项。这些条件提供了直接的调查入口：候选可能已经命中，但因所在位置被分到更低档，或在某个搜索入口中默认不展示。因此可以有针对性地追踪原程序的来源分级字段及后续显示分支。

这是解释差异的假设，尚未证明截图规则就是当前未知 64 位排序键的全部来源，也不能据此说明每个结果的实际排名。历史、应用来源和其他已恢复分组仍同时存在。

## 尚需只读核对

1. 分级分别作用于快捷栏和展开搜索的哪些阶段，“不常用”是否只是降级、默认隐藏，或随入口而变化。
2. 多条条件同时命中时如何决定结果；开始菜单等子路径是否覆盖不常用父路径，不能按截图行序直接推断。
3. 名称正则是否仅作用于文件、是否继承到目录后代；`^[^.]+$` 按名称正则解释为不含点的名称，但不能直接把所有普通目录判为不常用。
4. `.codex` 等点开头目录如何与历史优先级交互；截图本身不足以证明它应被隐藏或排后。
5. “不索引”与“结果降级/默认隐藏”必须分别核对；不能把低优先级目录从全盘索引中删掉。

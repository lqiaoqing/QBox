# 保留快捷栏分桶的优先级键离线对照

恢复设置编码、规则合并、引擎键及字段桥接之后，使用当前 C/D 索引和九类查询做了第二轮离线对照。**九类查询的首屏和指定目标排名均未改变；ANYconsole 和 `.codex` 的空历史排名仍为 84、21。** 本轮没有将模型接入正式版，也没有发布新 EXE。

结果说明，补齐普通文件的优先级键会改变大量混合桶结果，却不能单独解决这两个目录的首屏问题。下一研究重点是上游候选选择及来源分桶；不继续堆叠路径降级条件，也不把本次结果宣称为 Listary 实际排名。

## 与上次实验的区别

此前 A/B 将所有非保护项跨桶稳定移尾，导致 `.codex` 在 B 中退到 2018。该方案已经否决。

本次 C 模型使用已恢复的有效类别及合并公式，给普通 NTFS 来源计算键；只在当前混合桶原有位置之间重排。应用、便携 EXE、历史、强目录、弱目录及“混合前十/弱目录/混合尾部”的布局保持当前 QBox 策略。普通目录也计算类别和键用于核对，但当前目录桶按匹配分数排序，其位置未被键替换。

模型输入包括：

- 默认表 11 条路径、5 条名称规则。目录先查精确路径覆盖，随后按父目录继承、SYSTEM/HIDDEN 属性和首个适用名称规则合并类别。
- 从同一索引导出的 554,582 条目录记录，以及 4,780 条含 SYSTEM/HIDDEN 标记的名称。按文件身份和父身份回查，使用原始目标末级名称而非显示别名。
- HKCR 的 1,035 个 ASCII 注册后缀快照。后缀标记函数先做 ASCII 小写，再按末字符分组并比较完整后缀；不是只取最后一个点之后的扩展名。
- 已验证的引擎键算式。上下文关闭、原始尾值取零；同键保持原有顺序。

模型明确假设卷根从正常类别开始；目录路径采用与当前索引相同的首个长名称链；SYSTEM/HIDDEN 降级开关开启。完整 Unicode 路径规范化等价、原生上游有界选择、上下文来源、尾值语义和其他来源策略不在本次等价范围内。

打包应用的弱匹配也可能进入混合桶。它们没有 NTFS 身份，本次保留既有来源键，在报告中单独计数；没有把它们伪装成可计算的磁盘项。

“位置改变”表示完整候选中的排名变化，不等于相关性提高。原生模型赋值也不等于已经验证所有完整查询行为与 Listary 相同。当前首屏之前多为应用来源或按分值排列的目录，所以普通文件混合桶发生大幅重排时，首屏仍可能不变。

`.codex` 在模型中确实命中点开头名称规则，被赋为不常用类别 1；它仍在当前强目录桶第 21 位，没有再出现跨桶移尾导致的第 2018 位退步。ANYconsole 类别为正常 2，位置同样由现有应用/目录层次决定。这个区别进一步说明需要把优先级键与来源分桶分开验证。

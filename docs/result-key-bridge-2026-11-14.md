# 引擎排序键到快捷栏的字段桥接

本次接通前两份报告保留的“引擎结果到来源行”缺口，并为三个适配区间增加 128 组原始指令对照。当前产品仍为 0.1.3，未修改匹配、排序、用户历史或发布文件。

目标为 Listary 7.1.0.47，SHA-256 `f728593f86597b95d9ee79c03f8e7d313ca4c79a4bab8cf31f3768febeb8063f`。这里的链路来自定点静态分析，计算来自 Ghidra P-code；没有执行原程序查询，没有将反编译伪代码视为原始源码。

## 排序键的传递

| 结构 | 大小 | 排序键字段 | 相邻数值字段 | 分数字段 |
|---|---:|---:|---:|---:|
| 原生重建结果 | `0x78` | `+0x60` | `+0x58` | `+0x6c` |
| 中间查询接口记录 | `0x70` | `+0x60` | `+0x58` | `+0x68` |
| 应用来源行 | `0x58` | `+0x48` | `+0x40` | `+0x50` |
| 文件项 | `0xb8` | `+0xa0` | `+0x98` | `+0xa8` |

`0x141f83120` 按已选中的文件身份重建结果，调用 `0x141fc1000` 计算键并存到结果 `+0x60`。`0x141f98c70` 逐项重建成 `0x78` 记录向量，`0x141f7b2a0` 负责查询缓存及分页结果封装。

接口适配层的主要调用关系为：

```text
新查询：141598510 -> 1416954b0 -> 141f7b2a0
分页：  141598030 -> 141694840 -> 141f7b2a0
                              -> 141f98c70 -> 141f83120 -> 141fc1000

上述两个接口方法 -> 141595050 -> 1416dd460：0x78 -> 0x70
14028b520 / 14028bdb0 -> 1418836a0 -> 14154bb70：0x70 -> 0x58
文件/目录来源适配 -> 14154b800：0x58 -> 0xb8
元数据构造器 14062a730 / 140631c60：文件项 +0xa0 -> 元数据 +8
```

间接调用也有对应关系：查询对象虚表 `0x142cf5710` 的 `+0x20/+0x28` 分别指向 `0x141598510 / 0x141598030`，与 `0x14028b520 / 0x14028bdb0` 使用的槽位一致。前者为新查询结果转换，后者为分页结果转换。

中间转换器 `0x1416dd460` 原样传递 `+0x60` 的键；将相邻 `+0x58` 的无符号数乘 1000，溢出时取 `UINT64_MAX`；取原生 `+0x6c` 分数，重排或取反几个标记。尚未给相邻字段赋予确定的时间语义。

`0x14154bb70` 的 `0x14154bc38 / 0x14154bc67` 用一对 16 字节复制将中间记录 `+0x58/+0x60` 放到来源行 `+0x40/+0x48`。`0x14154b800` 的 `0x14154b9d3 / 0x14154b9d8` 再把它们复制到文件项 `+0x98/+0xa0`。因此，文件项当前键确实来自已恢复的引擎键，并非仅因两个字段宽度相同而推断。

这闭合的是该磁盘搜索接口的结果键传递。快捷方式、打包应用等其他来源的专有字段，以及 Launcher 的来源分桶仍需分别处理。

# 上游候选选择与来源分桶续记

本轮确认了原生引擎的有界候选选择和分页边界，并对便携 EXE 来源策略做了独立离线实验。**直接取消便携 EXE 提前桶会使 RTT Viewer 从第 3 跌到第 117612，不接入产品。** 当前正式版保持 0.1.3。

目标仍为 Listary 7.1.0.47，SHA-256 `f728593f86597b95d9ee79c03f8e7d313ca4c79a4bab8cf31f3768febeb8063f`。静态调用链来自本机二进制；原始指令对照使用人工候选，不是运行中的 Listary 搜索结果或性能采样。

## 已确认的选择与分页

`0x141fe0db0` 汇总各卷或分块的候选。最终处理分支检查查询对象首个标记及请求状态：需要结果且类别标记为 1 时，取查询 `+8` 的候选数量上限；当汇总条数大于该值时，调用 `0x141fb7f20` 做 nth 分区，随后把输出长度设为请求上限。上限为零有单独分支。其他分支只汇总计数而不生成这一结果向量，不能把标记 0 简称为“无限返回”。

候选记录为 24 字节：文件编号位于 `+0`、卷编号位于 `+4`、键位于 `+8`、分数位于 `+0x10`。选择算法的比较顺序为：

| 内部模式 | 主比较 | 同值比较 |
|---|---|---|
| 2 | 有符号匹配分数降序 | 卷编号升序、文件编号升序 |
| 0 / 1 | 无符号 64 位键降序 | 卷编号升序、文件编号升序 |

`0x141fb7f20` 只保证前 k 项集合和第 k 项满足分区条件，不保证前 k 项内部已经完整排序。它不是另一套名称匹配分数，也不能替代后续来源排序。该算法及辅助函数包含小集合插入、枢轴选择和分区路径；本次实际执行的函数入口计数保存在验证摘要中。

分页函数 `0x141f7b2a0` 的 `0x141f7b47e..0x141f7b4a4` 按以下算式限制请求区间：

```text
start = min(offset, cached_length)
end = min(saturating_add(start, requested_count), cached_length)
returned_count = end - start
```

因此，“首批候选选择上限”“已有结果缓存的分页”“快捷栏最终展示 9 项”是三处不同的数量控制。当前证据不支持把它们统一成“全盘只取前 9 项”。分页算式本轮为静态指令核对，不计入下文的选择指令样本数。

## 请求来源的证据边界

中间请求转换器 `0x1416dddf0` 保留首个数量标记及 `+8` 数量值。应用层 `0x1405e84c0` 从输入设置 `+0x38/+0x40` 取得这一对值，写到中间请求 `+0/+8`。

组合请求构造器 `0x14029c0a0` 明确构造三份请求：其中两份输入的数量标记为 1、数量为 50（写入点 `0x14029c262/26d` 和 `0x14029c601/60c`）；另一份标记为 0（`0x14029c3fc`）。它的调用点传入不同的排序/来源参数。

**尚未把这三份请求的每个用途完整连接到用户实际快捷栏入口，不能把 50 宣布为快捷栏统一候选上限。** 此构造器经过批量适配器 `0x141863ce0` 及调用方 `0x1402a23b0`；后续仍须给每个来源标记补齐业务含义。`0x1405e84c0` 的宽泛反编译曾因间接跳转扩展到函数区间外，本轮只采用 PE 异常表范围内的原始字段写入及调用证据，不采用越界伪代码结论。

单个候选入口 `0x141fe07b0` 在打分之前还检查类型掩码、优先级类别、数值范围、名称及其他可选谓词。类别 0 不进入结果；类别 2/3 归一为 2。这些过滤输入的完整 UI 含义仍未全部恢复，不能由函数中的分支数量推导已覆盖所有功能。

## 原始选择指令对照

新增 `scripts/research/QBoxReplayCandidateSelection.java`。目标二进制和六个允许执行区间均核对 SHA-256 后，执行选择函数及它的原始辅助函数，不替代比较、枢轴选择、递归或交换。

输入长度覆盖 1、2、3、8、16、17、51、64、127、256，k 覆盖合法的 0、1、中点、末项和 50；模式为 0/1/2；输入分别按原序、逆序、固定种子打乱，共 333 组。键包含最高位为 1、全 1 等无符号边界；分数包含正数、负数及有符号上下限，同键/同分依次检查卷和文件编号。

独立 Python 完整排序验证通过：

- 原始输入符合生成定义且身份不重复。
- 原始指令只排列候选，身份与全部字段均保留，前后边界保护区不变。
- 前 k 项集合、第 k 项和剩余集合与完整排序分区逐项一致。
- 改写原始输入、跨分区交换结果的两个反例均被拒绝。

首次大集合核对曾发现夹具的原始输入被改写。核查本机 Ghidra `MemoryPageBank.setPage` 后，确认整页写入可保留传入数组引用；将写入改为副本后重新执行全部 333 组并通过。这是研究夹具修正，没有修改原程序指令，也不构成 Listary 缺陷。

实际覆盖的函数入口为 `141fb7f20`、`141f8d210`、`141fb92b0`、`141fbe120`；允许区间中的深层退化回退 `141fb6fa0 / 141fb6db0` 未在本语料触发。完整查询、异常索引 panic、取消、缓存更新和并发一致性不在本次指令验证范围内。

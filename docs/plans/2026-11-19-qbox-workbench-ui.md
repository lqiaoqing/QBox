# QBox Windows 原生工作台 Implementation Plan

**目标**：先交付可日用的 QBox 新界面。完整窗口变成工具工作台，现有搜索直接可用；其他工具先能看到入口、页面和操作流程，后续逐项接入真实功能。

**架构**：基于 `codex/feat-new` 的 0.2.7，沿用 C# / WPF。沿用一个 `MainWindow`、一套搜索结果、一次索引载入以及现有托盘和热键入口。快捷搜索与完整工作台共用搜索控件和状态；未来工具的独立面板只做可点击预览，不进入日常热键链路。

**范围**：选此前确认的「Windows 原生工作台」，不再做三套视觉方向。不改 C# 默认引擎、匹配、排序、索引格式或实时更新，不做新的界面框架、通用模块系统或主题引擎。本轮完成后验收 UI，再另开功能任务。

## 1. 工作台外壳与导航

**改动**：`src/QBox.Desktop/MainWindow.xaml`、`src/QBox.Desktop/MainWindow.xaml.cs`。新建 `src/QBox.Desktop/Workbench/WorkbenchPage.cs` 表示页面，新建 `src/QBox.Desktop/Workbench/WorkbenchStyles.xaml` 集中定义新控件样式，由工作台范围引用。

1. 完整窗口上方保留标题栏，左侧依次为搜索、剪贴板、截图与贴图、桌面整理、翻译，底部固定设置；右侧为当前页面。视觉以原方案的浅色底、原生系统字体、低对比分隔及单一蓝色强调为准。明确区分悬停、选中、键盘焦点和禁用状态。本文只定控件和行为，不要求逐像素复刻预览。
2. 初始完整窗口可按约 `960 × 640 DIP` 布局，最终以可用屏幕为上限。内容区随窗口增长；窄窗先收成有文字提示的图标导航，右侧内容继续可用，不强行把整个窗口撑出屏幕。快捷模式隐藏左栏和工作台页，继续使用现有紧凑框和结果窗宽高。切换时各记自己的窗口尺寸，查询变化不会把用户拖大的完整窗口重置为默认高度。
3. 加一个独立的「打开工作台」托盘入口；现有「打开搜索」和托盘双击仍直达搜索。第一次打开工作台进入搜索，之后普通工作台入口恢复上次选中的工具页；快捷搜索展开时总是进入搜索页。第一轮只需在当前进程记忆页面，关闭再开不要求持久化。页签支持 Tab 和 Enter，非搜索按钮不拦截热键或输入法。

**验收**：从托盘分别打开工作台和快捷搜索；能切换全部页签；只在完整窗口看到侧栏。拖大完整窗口后输入搜索、切页、回快捷框，尺寸和布局符合预期。在 100% 和一种非 100% 缩放下查看，列表与底栏不被裁掉。

## 2. 把真实搜索接进新布局

**改动**：`src/QBox.Desktop/MainWindow.xaml`、`src/QBox.Desktop/MainWindow.xaml.cs`、`src/QBox.Core/Search/SearchChrome.cs`（仅当现有布局状态不足时）。复用 `ResultRow`、`LatestQueryGate`、`SearchResultActivation`、现有底栏和虚拟化列表。

| 当前状态 | 按现有搜索唤起键（默认双 Ctrl） | 界面按钮或退出方式 |
| --- | --- | --- |
| 隐藏 | 打开空的快捷搜索框，直接能输入 | 保持现有隐藏后重置规则 |
| 快捷框或结果列表在前台 | 展开到工作台搜索页，保留搜索词和选中目标 | 展开按钮执行同一动作；Esc 收起 |
| 工作台搜索页在前台 | 再按收起 | 右上角「切回快捷搜索」保持查询和选中项；关闭仍收起到托盘 |
| 工作台其他页在前台 | 直接切到工作台搜索页并聚焦输入，避免热键落到占位页 | 点击侧栏可返回原页 |
| 工作台在后台、但未隐藏 | 激活工作台并聚焦搜索页，不把后台窗口直接收起 | — |

1. `ApplyChrome` 只管紧凑、结果、完整三种外观，导航只决定完整窗口显示哪一页。搜索输入和结果列表保留同一实例；进入其他页停掉不再使用的前台搜索和图标任务，实时索引照常运行。回到搜索页如有索引更新，使用当前快照重查。
2. 快捷仍显示 8 行、最多 40 条；完整搜索仍先显示 200 条，再静默续填到最多 2000 条。进入完整窗口先显示已有结果；如果要补到完整列表，沿用现有查询闸门。切换前记录选中候选 ID；同一查询有替换结果时按 ID 恢复，目标不存在或缩回快捷上限时才退到首条。查询字串或版本变了，取消旧锚点，避免 Enter 打开旧结果。
3. 完整搜索页显示结果图标、名称高亮、路径、选中状态，以及底栏的耗时、命中数、显示数和索引状态。保留现有单击、Enter、上下键、Esc、复制路径及可选 Alt+数字。保持中文组合输入与列表虚拟化；不在界面线程为全部结果取图标或预加载其他工具。

**验收**：双 Ctrl → 输入 → 下移选中 → 双 Ctrl 展开 → 续填完成 → Enter，打开的仍是所选目标。再验证快速换查询不误开，中文输入可用、无命中正常提示、宽查询能从 200 续填到 2000，底栏显示耗时。工作台失去焦点继续显示，快捷搜索沿用现有失焦收起逻辑。

## 3. 先把其他工具的界面做出来

**改动**：新建 `src/QBox.Desktop/Workbench/ToolPreviewView.xaml` 和必要的代码后置；只有样式或交互明显不同才拆控件。预览数据放在预览控件中，明确标「界面预览 · 示例数据」。工作台页面提供「查看快捷面板」或「查看截图流程」，在 QBox 内部用托管的预览视图模拟。正式入口点击时可正常查看，但不会调用系统能力或申请权限。

| 工具 | 本轮能看到、能试的界面 | 后续才接入的能力 |
| --- | --- | --- |
| 剪贴板 | 工作台有左列表、右侧详情；快捷预览有搜索、类型筛选、置顶及最近分组，文字摘要、图片缩略图、文件名。演示键盘选择、纯文本入口和展开后保留筛选/选中项。粘贴按钮明确标为演示 | 复制监听、历史持久化、真实置顶、向原窗口粘贴；浮窗优先靠近输入位置，取不到时回退到光标附近 |
| 截图与贴图 | 工作台显示截图入口和用途；在示例区域演示悬停高亮、拖动选区和贴近选区的工具栏，取消退出预览。标注、复制、保存、贴图、OCR、翻译只做控件位置或示例跳转 | 对真实屏幕和窗口取图、识别窗口或元素、贴图、输出及 OCR |
| 桌面整理 | 显示规则列表、待整理项和整理前后预览，操作标明仅作用于样例 | 扫描桌面、创建规则、搬移文件、撤销 |
| 翻译 | 弹出紧凑预览，展示原文、译文和复制位置；展开到工作台后保留示例文本。截图预览可以将示例 OCR 文本送到翻译页 | 调翻译服务、读取剪贴板或真实 OCR 文本、复制译文 |

面板预览共用两个规则：展开带上该工具的页面状态；Esc/取消离开预览后，焦点回到原预览按钮。真实粘贴、截图和翻译面板后续接入时再实现交还原应用焦点，本轮不模拟向外部程序发键。

**验收**：能浏览四个工具页并试一次剪贴板展开、模拟截图转翻译、翻译展开。退出预览没有剪贴板、桌面文件、屏幕捕获或网络副作用。

## 4. 设置页面与热键边界

**改动**：新建 `src/QBox.Desktop/Workbench/SettingsView.xaml` 及必要的代码后置；改 `src/QBox.Desktop/MainWindow.xaml.cs`，与 `DesktopSettings.cs`、`HotkeyRegistration.cs` 的现有规则对齐。

1. 在设置页展示并接通现有搜索唤起键选项、结果快捷键、实时更新和数据目录。沿用现有设置对象、保存入口和索引命令，旧设置继续读得出来。切换真实搜索唤起键时先确认注册成功，再保存；失败保留旧值并显示原因。菜单入口保留可用，共用同一个操作处理函数。
2. 集中列出未来默认组合：剪贴板 `Ctrl+反引号（~ 同键）`、截图 `Ctrl+1`、翻译 `Ctrl+2`；桌面整理暂不设默认。统一标为「未启用」，UI 阶段不注册系统热键、不占用其他应用的组合键。页面预留未来的按键录入、重复提示、禁用、恢复默认入口；搜索本轮继续使用已有可用选项，不扩大热键识别范围。

**验收**：现有搜索键能改、能恢复，遇到占用不丢旧键；未启用的组合键按下不影响其他应用。旧目录内的设置和历史继续可读，不做数据迁移。

## 5. 轻量验收与交付

先做 1、2，交付一个真实可搜的工作台，再做 3、4。样式调整用一次手工快检即可；收尾复用已有检查，不新建测试框架：

```powershell
pwsh -NoProfile -File scripts/verify.ps1
dotnet run --project tools/QBox.DesktopProbe -c Release -- work/workbench-ui-probe/state
```

- 自动检查应全部通过。若探针用到的原 WPF 控件名变动，更新它的定位。用现有隔离样例，回归已认可的七类查询 `Any`、`800Q`、`.code`、`nd`、`Tra`、`chatgpt`、`rtt`；核对命中数和前几条顺序，不重建生产索引。
- 最后用同一个 Release 包走约 10–15 分钟：托盘打开 → 双 Ctrl 链路 → 中文输入 → 宽查询首批与续填 → 页面切换与预览 → 设置 → 关闭回托盘。与 0.2.7 同索引快速比一次宽查询的可见首批和再次唤起；底栏耗时不当作窗口绘制耗时。如果发现明显变慢，再针对该路径复测。
- 交付一份隔离试用包和几张实际界面截图（完整搜索、紧凑结果、一个工具预览、设置）。用 `scripts/publish-desktop.ps1` 输出到 `work/workbench-ui-preview`；验收前不覆盖正式包。用户确认工作台顺手后，再决定先接哪个新工具；无需在 UI 阶段建立所有工具的后端接口。

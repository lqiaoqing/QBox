# QBox 全局搜索设计

## 目标与边界

先实现独立全局搜索，再扩展工具箱。用户的标准是本人使用 Listary 快捷搜索栏时的覆盖、相关性、响应和学习行为；五个截图样例只是回归样本。禁止按样例路径、软件名或查询硬编码提权，禁止通过截断索引或候选来掩盖遗漏。

用户已授权按“匹配与历史排序 → 全盘索引及更新 → 快捷栏 → 实际验收”的顺序实施，不重复请求阶段启动许可。不修改 Listary 的安装文件、配置或历史，不收集其性能数据。不执行 Git 暂存或提交操作。

## 技术选择

采用本机已有的 .NET SDK 10.0.110 / C#，核心库不依赖 UI。相较需要安装新工具链的 Rust/C++，可以直接编译和验证；索引使用紧凑记录和名称存储，避免为每个文件构造完整路径对象。Windows 界面后续使用独立桌面项目。

核心匹配器先建立顺序匹配筛选，再求最优对齐及高亮位置。ASCII 内部分值逐例与原始指令模拟器比较，测试语料包含连续、跨词、大小写、数字、标点、重复字符及随机输入。Unicode 路径必须正确表示，不能把非 ASCII 转成问号；拼音规则在尚未恢复时明确列为未完成。

历史按稳定目标标识保存。只有成功执行选择操作才写入，普通查询不改变历史。每个目标维护最近 8 条查询关联，全局最近查询维护 500 条；相同查询时间优先，其次历史查询以前缀关联当前查询的时间，再保留目标最后访问时间。存储采用版本化 JSON、同目录临时文件及原子替换，损坏文件保留并报告。

排序把相同查询历史、前缀历史和普通候选分开处理。已恢复的规则和 QBox 尚待校准的普通排序规则在 API 与文档中明确标记。检索先决定是否匹配，再排序，不能用历史分数让不匹配项进入结果。

## 工程结构

- `src/QBox.Core`：匹配、历史、候选、排序和搜索契约。
- `src/QBox.Cli`：可运行的查询与案例验证入口，不负责索引权限。
- `tests/QBox.Checks`：不依赖外部测试包的自动验证程序，使用独立 fixtures 和原指令 oracle。
- `src/QBox.Windows`：后续 NTFS/MFT、USN、应用及快捷方式来源。
- `src/QBox.Desktop`：后续快捷栏与启动动作。
- `work/research`：现有静态研究及模拟器，产品运行不加载或调用 Listary。

## 后续阶段

索引必须区分可用、初建中、追赶日志和需要重建状态；处理日志 ID 变化、断档、卷离线、改名移动和硬链接。需要权限的安装操作在可审查的程序与安装步骤准备好后再处理，不能预先假定能读原始卷。

快捷栏保留异步取消及输入版本号，旧查询不能覆盖新查询。首次试用避免抢占正在运行的 Listary 快捷键。实际验收由用户正常使用判断，未达到要求时继续定位差异，不能宣布成功。

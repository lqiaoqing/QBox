# QBox Rust 对齐 C# 0.2.5：剩余工作 Implementation Plan

**目标**：把现有纯 Rust 试用版补成可替代 C# 0.2.5 的 Windows x64 版本。多卷实时更新、旧数据升级和日常操作要能用，搜索速度不能退化，空闲占用要有同口径结果。

**做法**：在 `QBox-rust-engine` 工作树的 `feat/windows-rust-parity` 上继续。复用 Rust 搜索核心、当前桌面界面、Windows Shell 和现有 worker 协议；用 QBI 基础索引加 QBD 增量维护每个卷。本文是[原 P0–P7 计划](2026-11-18-qbox-rust-windows-parity.md)的续做清单，任务按下列顺序推进，验证以本文为准。

## 开工前：认领已有进展

- 本次核对的 Rust 提交是 `f484f60`，C# 对照是 0.2.5、冻结源码 `1f06daa`。开工时看一次 `git status`、`git log -1` 和 Rust 工作树的 `docs/2026-11-17-纯Rust重写/PROGRESS.md`。若他人已经补上某项，核对出口后接着做。
- 直接复用：冻结样本的 21 条查询、650 条结果排序对照；真实单卷增量和合并接续；现有 UTF-16 目标解析、历史、三态界面及 CLI。旧性能对照的应用目录和历史条件不同，不能当最终结果。不重做 T00–T10，也不在 P2 停下来等排期。
- 开发时使用独立 Rust 状态目录、独立索引和自建文件。旧用户目录及冻结对照只读。这里的文件路径均相对 Rust 实施工作树；完成一项就在 `PROGRESS.md` 写提交、做了什么、实际结果及未验证项。若缺第二个卷或测试机器，先继续不依赖它的任务，最终保留缺证据的发布阻塞。

## 1. 让桌面同时搜索、更新多个卷（P3）

**差距**：GUI 只打开一个卷、切换时停止原来的监听；worker 会拒绝 `Start.volumes` 中有多个卷。C:、D: 各自跑通过，不能证明它们能一起工作。

**改动落点**：`rust/qbox-app/src/{volume_layout,trial_settings,search_service,watch_client,worker,index_build}.rs`，`rust/qbox-desktop/src/main.rs`。对照 C# `src/QBox.Desktop/LiveIndexWorker.cs` 的固定 NTFS 卷选择。

1. **卷按真实身份绑定。** 枚举就绪的固定 NTFS 卷。盘符是入口，NTFS serial 决定 `indexes/<serial-16hex>/` 和状态键；同一 serial 只接一次。写前用已打开卷的几何信息核实 serial，读前核实世代属于该卷；不能拿上次选择的 serial 配新盘符。复用 `volume_layout.rs` 认领已有单卷目录，验证通过才迁移，遇已有目标目录不覆盖。GUI 的卷选择只用于状态和手动操作，默认搜索覆盖所有已就绪卷。
2. **每卷一份查询视图。** 复用 `SearchService::reload`、`refresh_incremental`、`adopt_generation` 维护每卷现有视图，应用层组装一份可共享的多卷快照。更新一个卷只替换该卷条目，其他卷共享原视图；查询固定卷集合、目录、历史和版本，沿用已有多卷归并、身份与排序。旧请求不得覆盖新结果。不要为每个卷再复制一份应用目录或历史。
3. **给现有 worker 接多卷。** 沿用一次提权、一次 `Start`、已有 `volumes` 数组、租约和当前协议，补齐按 serial 分发每卷状态、已持久检查点和发布通知。每卷锁及落盘继续走现有逻辑，保留普通用户 token 写索引。复用单卷刷新和合并；同一时刻最多一个全量建库、重建或重合并任务，其他就绪卷仍可搜索、追赶。立即同步复用当前 writer，暂停和退出沿用现有控制，不起第二个 writer。
4. **故障局限在一个卷。** 断档、离线、拒绝提权或构建失败时保留最后可用索引，说明该卷是否停更。恢复后从最后持久点续跑，确实断档才走该卷重建。安装后的自动更新开关以冻结 C# 实际默认值为准；保留迁入的显式设置。一次启动内拒绝授权后继续只读搜索，等用户手动重试，不循环弹窗。退出结束所有卷任务并回收本会话 worker。

**出口**：两个真实固定 NTFS 卷同时可搜；各自新建一条唯一命名文件，保持查询打开，两条都自动出现；再挑一卷改名或删除。停掉或断开一个卷时，另一卷新增仍可查。重启后能追上停机期间的变化，退出无本会话 worker。实现阶段复用 `qbox-app` 已有的增量刷新和世代接续用例，再跑两卷新增路径；旧 serial 配新盘符导致串写是新增边界，补一条拒绝该配对的回归即可。故障、UAC 和退出合到最终走查。

## 2. 升级接续旧设置、历史和索引，确认真打开（P4）

**差距**：旧状态导入能读文件，但没有桌面升级入口；输出还带 `indexDirectory`，Rust 桌面现有设置解析器不接受它。AppX 已能搜到和解析，仍缺真实启动证据。

**改动落点**：`rust/qbox-app/src/{legacy_state,trial_settings,history_store,search_service,activation,native_target,commands}.rs`，`rust/qbox-engine/src/legacy_import.rs`，`rust/qbox-desktop/src/main.rs`。

1. **桌面加显式导入。** 首次使用或从设置进入，默认检测旧目录，显示来源供用户确认。复用 `import_legacy_state` 的校验，将旧设置转换成实际可加载的 Rust 设置，保留热键、自动更新、Alt+数字；旧 `indexDirectory` 用来找源索引，Rust 写入独立目标。支持 `--state-directory`、`--index-directory`、`--start-hidden` 的公开用途：命令行优先，目标 Rust 数据和旧只读来源区分清楚。保留已有 Rust 参数；若指定旧格式，只读打开或提示导入，不能就地改写旧索引。
2. **成功才启用。** 先写临时目标并按实际 Rust 加载器读回，成功再在同级切入目标；不要覆盖已有 Rust 历史或设置，失败后可以清理本次临时目录并重试。优先复用旧索引导入能力和任务 1 的 per-serial 路径。损坏或不能继续追赶的卷提示重建，不拖住设置、历史和其他卷。没有索引时仍可用应用搜索。
3. **历史确实参与排序，打开确实打开对。** 优先复用稳定 ID 和已有唯一映射；有硬链接歧义、同名不同目标或 FRN 复用时不猜。继承历史后，同一查询应能看到原有常用目标的排序信号。确认激活的是当前结果的原生身份，文件/目录按宽字符路径，`.lnk` 保留参数和工作目录，AppX 按 AUMID 启动；只有实际启动调用成功才学习。只修实测发现的差异，不调权重。

**出口**：用一份旧状态副本导入，重启后验证热键、索引及历史排序；再导入不会覆盖，失败可重试，旧设置、历史和索引哈希不变；回开 0.2.5 仍能用旧状态。实机点开一个有区分度的普通快捷方式、中文路径或同名文件中的正确目标，以及一个可确认窗口的已安装 AppX。失败打开不写历史。新单测优先补“导入结果可由桌面实际加载”这一处断点。

## 3. 桌面实用功能与托盘资源（P5）

**差距**：三态窗口已做，主要差在操作细节、缓存回收和实测。Rust 隐藏时已清掉结果、取消查询，并裁剪 GUI 和 worker 工作集。单卷记录的 GUI 工作集 13–40 MB 不能证明总占用更低；同一记录的私有提交仍约 956–1,080 MB，且没有 C# 同条件数据。

**改动落点**：`rust/qbox-desktop/src/main.rs`，`rust/qbox-app/src/{window_state,query,search_service}.rs`，必要时 `rust/qbox-platform/src/windows/{desktop_host,hotkey}.rs`。对照 C# `MainWindow.xaml.cs` 的 `OnIdleReclaim`、`ShellIconLoader.cs`、`LiveIndexWorker.cs`。

1. **沿用现有 UI，只修操作差异。** 验证双 Ctrl 唤起可立即输入、再次双 Ctrl 展开并保留查询和选中项，再次唤起可隐藏；快捷 40 条、主界面先 200 后补到 2000。刷新与续填按候选 ID 保持选择，连续输入不能打开旧结果。走一遍中文输入法（组合中的 Enter 先提交文字）、复制路径、Alt+数字开关、托盘唤回、快捷键占用回退及非 100% DPI 定位。纯像素差异后排；输入、打开或唤起受影响则修。
2. **先做小而确定的回收。** 给 Shell 图标纹理缓存和待加载队列设上限；隐藏时停止发新图标请求，忽略过期加载返回，延时回收可重建图标缓存。复用现有隐藏计时逻辑，取消搜索，按需释放未引用旧快照、临时结果和有证据的路径缓存。保留热查询所需的基础视图；不要靠卸载整份索引、反复裁剪工作集或换界面框架来压数字。检查同步和合并结束后临时数据是否退出生命周期。
3. **把 CPU 和内存一起看。** 最终对照采 GUI 和所属 worker 的私有提交及各自工作集，同时测重新唤起的第一搜。如果 Rust 私有提交明显偏高，先按卷查重复物化、长期持有的旧快照，再查已识别的大缓存。只有 CPU 实测偏高且采样指向约 10 ms 的热键轮询，才改唤醒方式；改后回归双 Ctrl 和自定义键。不在数据出来前开新优化项目。

**出口**：上述操作一轮能通过；空闲资源不发生超出测量波动的可重复退化，显隐及同步结束后不出现持续增长，热唤起和第一搜不变慢。内存比 C# 低多少随实测报告，不预设降幅，也不拿裁剪后的工作集代替私有提交。

## 4. 补 CLI 剩余兼容（P6）

**差距**：现有公开命令大多能用。`index-build`、`index-sync` 仍写平面 `.qbi`，还没接原方案约定的托管存储；应先确认脚本可见行为，再收口写入路径。

**改动落点**：`rust/qbox-app/src/{commands,index_build,search_service}.rs`，`rust/qbox-engine/src/generation_store.rs`，`rust/qbox-cli/src/main.rs`。公开契约对照冻结 C# `src/QBox.Cli/CliApplication.cs`，存储按 `docs/2026-11-17-纯Rust重写/STORAGE.md` §9。

1. 保留原有命令名、来源互斥、默认限制、结果字段、stdout/stderr 和退出码。`--search-engine rust` 兼容；显式 `csharp` 清楚报错。已有证据覆盖的命令不逐项重测，只跑这次改到的入口。
2. 新建索引将 `--index` 当作逻辑入口，照 STORAGE §9 的 `QBXLOC01` 格式使用相对 sidecar，复用任务 1 的世代、锁和更新函数。`index-info`、`search`、`open` 认 locator，也继续只读识别旧 `.qbi`；缺 sidecar 要报错，不能回退成空库。显式同步旧入口时先备份，待新 store 验证后再原子切入口。断档返回需要重建，不能报告同步成功；失败或取消保留原入口。CLI 与 GUI 指到同一卷存储时共用写锁。

**出口**：用一个隔离样例串跑 `build → info → search → sync`，验证旧索引还能查、断档或 Ctrl+C 不损坏旧入口。复用已有 `search` 不学习、`open` 成功才学习的测试；只有变更涉及该路径时重做实机打开。

## 5. 一个候选包，一轮验收，再切换（P7）

1. **先打包，不改默认。** 新增 `scripts/publish-rust.ps1`，从锁定依赖构建桌面和 CLI，输出 `QBox.exe`、`qbox-cli.exe`、必要资源、许可与升级/回退说明。在源码树外运行，记录提交、文件大小、SHA-256 和构建命令。报告两版实际分发大小及所需运行时，避免把旧单个 EXE 和 Rust 全包直接相减。优先验证正确打包；体积压缩不单开项目，有低成本改动时只在冻结候选前做并复测启动。
2. **走查 20–30 分钟。** 同一候选包内合并验证：导入及重启 → 双 Ctrl/IME/打开目标 → 双卷各自变更可见 → 暂停、恢复和一次合并 → 拒绝授权仍能搜并可重试 → 退出后确认活跃的 worker 不残留。索引初建和环境准备不计入走查时长。任务 1–4 已用同候选取得的证据可直接合并，无需重复跑。真实测试盘上只动自建样例，不人为破坏用户 USN 日志；断档恢复复用已有回放证据与受影响路径的检查。
3. **做一张短对照表。** 同一机器、两版 Release 轮流运行，卷范围、索引内容、应用目录、历史、结果上限及实时更新开关相同。七类 `Any`、`800Q`、`.code`、`nd`、`Tra`、`chatgpt`、`rtt` 加 `1`、`python`、一条中文和一条可命中的拼音：一次核结果数与前十身份，再取同样一次预热后的 3 次快捷框首屏；主窗口选一个宽查询测 200 首批和 2000 续填，各测一次冷启动首次可搜及热唤起。计时到同语义的首批可见结果，内核耗时另列；只有差异超过波动、有可疑回归时再加一轮。资源同次采：两版都搜过同一批查询、隐藏 30 秒后记分进程工作集及 GUI+worker 私有提交合计，并记录随后 60 秒的 CPU 时间增量；另记一次同步峰值及变更可见的时间。同步期间和无变更空闲不能混采。
4. **只在达到门槛后改入口。** 关键条件必须有实据：搜索无可重复变慢、已索引变更能看见、打开的是正确目标、拒绝授权或重启能恢复、升级保留旧数据、退出无 worker 残留。空闲资源明显变差也先定位；不以工作集单项改善抵消私有提交、CPU 或第一搜退化。若没有能比较首屏的观测点、没有无 .NET 桌面运行时的 Windows 验证环境，照实标未验证，默认入口、根 README 和 CI 保持原样。能比较行为但像素没完全一致，可记入后续项。
5. **通过后收口。** 只在实施分支切换 `README.md`、开发指引、`scripts/{dev,verify,publish,publish-desktop,check-repository}.ps1` 和 `.github/workflows/windows.yml` 中实际走 C# 的默认入口。活动产品构建不带 .NET、FFI 或 C# 回退；保留冻结基线及发行历史。切换后用默认命令打一次包并冒烟；若产品二进制变化，按影响复测对应路径。是否合并或发布另行安排。

测试命令从 Rust 工作树根运行。单项用 `-p` 和测试名选择受影响的现有用例；最终候选只跑一次完整检查，成功返回 0：

```powershell
cargo test --manifest-path rust/Cargo.toml --locked -p qbox-app
pwsh -NoProfile -File scripts/verify-rust.ps1
cargo build --manifest-path rust/Cargo.toml --release --locked -p qbox-desktop -p qbox-cli
```

**记录只用一处**：在 Rust 工作树的 `PROGRESS.md` 记候选包哈希、通过/失败/未验证、证据位置和剩余阻塞。交付一份 Rust 包、一张短对照表、升级和回退步骤。没有迹象表明存在持续增长、时序问题或间歇故障时，不加长稳、测试矩阵、新验证器或重复基线校准。剪贴板、截图、翻译、macOS 和界面框架更换都不在本轮。

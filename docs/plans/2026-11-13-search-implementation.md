# QBox Search Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 按用户确认的顺序实现独立的匹配与历史排序、全盘索引、快捷搜索栏及实际验收。

**Architecture:** 核心库与 Windows 平台/UI 分离。原程序仅作为离线研究和测试 oracle，产品不依赖它。每阶段保留真实完成范围，未恢复行为不冒充原算法。

**Tech Stack:** C# / .NET 10，Windows 桌面与原生接口；第一阶段零外部 NuGet 依赖。

---

## Task 1：建立可构建工程

创建 `QBox.slnx`、`global.json`、`Directory.Build.props`、`NuGet.Config`、`.editorconfig`、`.gitignore`、`README.md`，以及 Core、Cli、Checks 项目。

1. 固定已安装 SDK，配置离线框架引用和编译告警。
2. 创建核心 API、CLI 和验证程序入口。
3. 运行 `dotnet build QBox.slnx -c Release`。

## Task 2：独立匹配器及 oracle 核对

创建 `src/QBox.Core/Matching/` 下的 `FuzzyMatcher.cs`、`MatchResult.cs` 和相应验证代码。

1. 增强研究模拟器，允许从文件读取新的 ASCII 对照样本；保留辅助函数模型及失败标记。
2. 首先建立连续、间隔、词边界、重复字符和非命中语料，使未实现模块的检查失败。
3. 实现大小写不敏感的有序筛选、最优对齐、分数和 UTF-16 高亮位置。
4. 比较原始指令输出；将未匹配的样本作为缺陷处理，禁止加入按名字判断的例外。
5. 增加 Unicode、补充平面字符和长名称的边界验证；未验证等价的范围单独报告。

## Task 3：历史记录及分组排序

创建 `src/QBox.Core/History/`、`src/QBox.Core/Search/` 及 `tests/QBox.Checks/` 对应检查。

1. 验证不选择不写入、每目标 8 条和全局 500 条、去重及稳定目标身份。
2. 实现相同查询和前缀关联查询的时间读取，匹配失败不得因历史进入结果。
3. 实现版本化原子保存、重启读取及损坏文件保护，使用测试临时目录验证。
4. 核对已恢复排序分组；普通排序未确认的元数据明确列入待办。

## Task 4：可运行的第一阶段入口

在 `src/QBox.Cli` 提供自定义候选 JSON 查询、历史记录和交互命令；运行时从参数读取数据，不内置截图目标。

1. 用候选文件验证五个查询的匹配及高亮。
2. 用实际选择前后、重启后对照验证历史学习。
3. 运行 `dotnet run --project tests/QBox.Checks -c Release`，输出已通过范围和未完成范围。

## Task 5：全盘索引与更新

第一阶段基础检查通过后，添加 `src/QBox.Windows`。先实现卷/权限发现、MFT 初建、紧凑名称记录，再实现 USN 更新、重命名移动、硬链接及断档重建，最后补齐应用和快捷方式来源。按生成的临时文件验证每条变更路径，不改用户实际文件或 Listary 数据。

## Task 6：快捷栏与实际验收

添加 `src/QBox.Desktop`，实现异步查询、输入版本隔离、键盘选择和实际打开目标。历史只在启动成功后记录。试用快捷键与现有 Listary 避免冲突；不擅自修改它的配置。

编译、自动检查和五个回归样本均不等于 Listary 水平的验收。实际使用标准仍待用户确认；无需再次收集 Listary 性能数据。

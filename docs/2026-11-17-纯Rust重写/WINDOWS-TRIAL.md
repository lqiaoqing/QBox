## 2. 用户拿到的版本

- **搜索是日常主入口。** 隐藏时双击 Ctrl 唤起快捷搜索框并获得输入焦点，再次双击 Ctrl 进入主界面的搜索面板，保留查询和当前选择。主界面可以直接搜索和设置。快捷结果最多 40 条，完整界面先出 200 条，再按已有规则续填至最多 2000 条。上下键选择，Enter 或单击打开，Esc 或关闭按钮收起到托盘，托盘提供打开和退出。
- **先支持能实际打开的对象。** 可搜索文件、目录、当前用户及公共开始菜单里的普通快捷方式。沿用已有英文、数字、缩写、中文、拼音匹配、排序和历史学习。首包说明应用覆盖范围，单独标出尚未接入的 AppX/AUMID 来源。
- **索引采用手动同步。** 首次启动选择一个 NTFS 卷，点“建立索引”。之后从本试用版的已提交索引直接启动，设置中显示卷、上次成功同步时间、当前状态和“立即同步”。新建、改名、删除在下一次成功同步后反映。试用的目标是验证查询体验，先接受这个可见的时效取舍。
- **运行与数据独立。** GUI、搜索、索引和 worker 均走 Rust。包可从独立目录运行，使用专属设置、历史、索引、日志和实例标识。读取已有试用快照无需提权，只有确需读卷时请求 UAC。冻结的 C# 程序仅用于对照。
- **后续产品方向。** 保留“快捷动作 + 主界面配置”的交互。剪贴板（默认 Ctrl 加反引号键）、截图（Ctrl+1）、翻译（Ctrl+2）、桌面整理、自定义组合键及 macOS 留在后续产品计划。本轮只绑定搜索，交付界面只展示已可用的功能。

## 3. 实施顺序和完成条件

下列源码路径相对于 Rust 实施工作树。每一步都通过同一桌面程序累积交付，最早在 A 完成时就能展示用户操作。

### A. 接通一个真实卷的搜索和打开

1. 从 T10 已发布的独立试用索引开始。在 `rust/qbox-app/src/search_service.rs` 接入 `rust/qbox-engine/src/generation_store.rs` 的当前已提交世代读取，复用清单校验和 reader 锁。使用对应基础索引和已提交的变更前缀。若首包只支持 T10 的空增量，遇到非空增量必须明确提示并支持从卷重建试用索引，不能静默漏掉变更。正常启动不依赖 `work/rust-baseline/indexes`。
2. 在 `rust/qbox-desktop/src/main.rs` 接入 `qbox-app` 的 `QueryGate` 与 `SearchService::search_with_cancel`。新输入取消旧查询，后台最多一个正在执行和一个待执行的最新请求。搜索期间由任务持有请求和快照，查询返回后再释放；输入、隐藏、快照替换后，旧结果不得覆盖新结果。续填使用同一输入和快照。
3. 接入 `rust/qbox-app/src/activation.rs` 和 Windows Shell。用结果自身的原生路径或目标标识打开文件/目录；显示文本只用于绘制。处理 `rust/qbox-engine/src/qbi.rs` 中 v3 名称转 String 的有损路径：搜索结果到激活目标须保留原始 UTF-16 身份。对当前尚不能精确解析的目标，显示明确失败并跳过学习，绝不打开近似同名项。先保证身份正确，是否重写整段热路径由实际性能决定。

**出口**：用桌面程序从真实世代找到一个文件和一个目录，Enter 与单击均能打开正确目标；连续输入后立即按 Enter，只能打开当前查询已显示的选中项。保存可运行命令即可进入 B。

### B. 让搜索成为可日常使用的快捷工具

1. 对接 `rust/qbox-app/src/window_state.rs`、托盘与全局双 Ctrl。复用窗口状态和分页逻辑，在 IME 组合输入时 Enter 优先确认输入。结果刷新保留仍然有效的选择。普通 Ctrl+C 等组合不能误唤起。第二次启动激活已有试用实例。若正式版也监听双 Ctrl，提供从托盘进入的路径，并在试用说明中写明独占验证方法，由用户决定是否暂退另一实例。
2. 开始菜单枚举放在查询热路径外。复用 `rust/qbox-engine/src/catalog.rs` 的候选和排序，普通 .lnk 由 Shell 打开以保留目标参数及工作目录。应用可从快捷与主界面搜索；打开成功后再通过现有历史模块写试用历史。历史写失败只提示，不重复启动。
3. 主界面提供搜索、索引设置和状态。隐藏时停止无事可做的查询与重绘，退出时结束本实例启动的任务。首次加载或同步暂不可用时给出可操作的界面反馈。

**出口**：从托盘和双 Ctrl 均能进入；快速输入、展开主界面、上下选择、打开普通快捷方式、收起、再次唤起均可用。重启后能读取本次试用的设置和成功打开记录。

### C. 接入首次建库和手动同步

在普通权限 GUI 发起 `rust/qbox-app/src/worker.rs` 的现有客户端调用，复用 `index_build.rs` 中的一次构建/恢复和发布。手动模式下一次请求只产生一次同步结果，成功或失败后有序结束作业和 worker，跳过持续 watch。忙碌时合并或禁用重复请求。跨权限读卷和缓存写入沿用 T09 既有通道和普通用户身份。

首次无索引时可见“建立索引”。同步时继续查旧快照，新世代完整加载成功后切换，并用当前输入刷新。取消 UAC、同步失败或加载失败时显示原因，保留上一可用快照及其成功时间；首次失败可从同一入口重试。退出、重启时只认已提交数据。

**出口**：从空的试用目录启动，在 GUI 建库并查到样例；在卷上新建、改名、删除样例文件，手动同步后看到最终状态。拒绝一次 UAC 后仍可查询已有数据。退出后本试用版的 worker 结束，重启能复用索引。

### D. 打包并作一次交付判断

从实施工作树根目录构建 `cargo build --manifest-path rust/Cargo.toml --release --locked -p qbox-desktop`，按该工作树实际 target 目录取产物。将 EXE、必要运行资源、许可和一页试用说明放入独立目录。说明写清启动、首次建库、双 Ctrl、手动同步、退出、试用数据位置和已知限制。把包复制到源码树外另一个普通目录，从那里实际启动，完成下节的一条路径；确认不依赖开发夹具、.NET 进程或 C# 引擎回退。

**出口**：交付可访问的包路径、对应提交、启动方式、简短实测结果和已知缺口。用户可以直接开始试用，到此结束本轮。

## 4. 最少且足以作判断的验证

| 何时 | 执行 | 何时停止 |
|---|---|---|
| 每次功能修改 | 运行受影响 crate 的现有快速检查。改动查询或排序接线时，用同一份索引回归 `Any`、`800Q`、`.code`、`nd`、`Tra`、`chatgpt`、`rtt`，另取已知中文/拼音命中样例。检查首项、顺序和可打开目标；应用来源有差异时单列 | 定位到真实回归才加一条针对性用例，已有检查覆盖的直接复用 |
| 交付前一次桌面走查 | 用交付包走“首次建库 → 双 Ctrl → 搜索/连打/中文输入 → 再次双 Ctrl → 打开 → 隐藏再唤起 → 手动同步 → 退出重启”。用自建无害文件夹、文件和快捷方式。补查旧结果不可误开、取消提权保留旧索引；与开发中已验证且产物一致的步骤共用记录 | 操作链通过、错误有反馈，写下包版本和观察结果。缺少交互权限的步骤标为待实机复核 |
| 交付前一次性能对照 | 同机、同电源、Release、相同卷数据/目录来源、查询、结果上限和缓存条件，复用现有探针。快捷框取 40，主界面首批取 200。记录冷启动首次出结果和热查询输入到首批可见的耗时，二者分开；热查默认做 3 对交替短轮，每轮每条预热 1 次、计时 5 次。报告中位数、尾部观测及原始值位置；能测到的核心查询耗时另列。给出双 Ctrl 到可输入的实际观察 | 发现可重复变慢时，先查具体查询、加载/取消/绘制阶段，只复测受影响项。输入条件或计时边界不可比时注明缺测，不能用内核数字代替桌面体验 |
| 同次运行观察后台成本 | 在相同卷、相同加载状态下，记录建库/同步期间峰值，及隐藏后同一时点（例如 30 秒）两版 GUI 与所属 worker 的工作集、Private Bytes、同一空闲窗口内 CPU 时间差；注明 worker 是否运行。指标标清单位，工作集与私有提交分别比较 | 一张对照表即可。以前的 123.7 MiB 是特定 Rust 对齐实验的私有提交差，不能充当本试用包的内存收益 |

**如何判定**：搜索/打开错目标、已提交索引丢失、无法独立启动，或同条件下可重复的搜索速度退化，均须修复后再标记试用达标。若个别性能数字受噪声影响或实机项目缺测，可附上包供体验，结论写为“功能可体验，具体指标待确认”，列出对应项。用户对正式替换的搜索速度不降级要求继续有效。有限试用数据只能支持其实际测过的路径。

# QBox 纯 Rust 重写实施方案

日期：2026-11-17（Asia/Shanghai）

状态：方案已整理，尚未开始实施；技术选型与性能结论仍需验证。

源码基线：`codex/feat-new`，`1f06daa0c9a9f29d8acbce357d169485afda92a4`。

## 1. 目标与实施边界

将当前 feat-new 的完整产品能力重写为 Rust，消除 C# 与 Rust 双实现、跨语言调用、重复预处理和回退带来的复杂性。搜索行为保持一致，搜索速度与整体性能不允许出现确认的退化。

技术上可行不等于已证明性能达标。Rust 语言本身不是性能证据；所有采用与替换结论必须来自同条件对照。本文是交给执行代理的方案，不代表已经实施、完成测试或批准正式替换。

### 本次交付范围

| 能力 | 要求 |
|---|---|
| 搜索 | 文件、目录、应用、快捷方式；字面、拼音、预筛、排序、高亮与历史 |
| 索引 | NTFS 初建、USN 增量、保存/加载、后台合并、恢复与重启 |
| 桌面 | 快捷搜索框、完整搜索界面、设置、托盘、单实例、全局热键 |
| 系统集成 | 图标、打开目标/位置、复制路径、应用启动参数、权限隔离 |
| CLI | 保留当前有效命令、输出含义与退出码行为 |
| 后续工具 | 预留剪贴板、截图、翻译、桌面整理的接入边界，本次不实现这些新功能 |
| macOS | 本次设计平台接口；完整实现与实机验收后续单独开展 |

默认先完成 Windows x64 的功能和性能对等，再展开完整 macOS 产品。完全 Rust 指应用自身的界面、搜索、索引、后台和业务代码均为 Rust；调用操作系统 API 属于平台集成。新产品不依赖 .NET、WPF、C# DLL、C# 后台进程或 C# 回退。也不使用 WebView/JavaScript 前端代替 Rust 界面。

开发期允许用冻结的 C# 程序和探针离线对照；它们不得成为新产品的构建、运行或发布依赖。历史 release 档案保持只读，不在本次任务中删除。

### 执行纪律

- 开始前重新核对 feat-new 提交；若已前进，记录新增差异并冻结唯一基线，不混用不同版本的结果。
- 从基线建立独立分支 `codex/full-rust-rewrite`，使用独立工作目录、状态、历史和索引副本。
- 不合并其他 worktree。v3 对齐等实验只作设计参考，不继承其“已通过”结论。
- 不修改正式索引、用户历史、设置、业务文件、其他 worktree 或无关未跟踪内容。
- 各阶段验证通过后按 AGENTS.md 提交相关改动；不自行 push、合并或替换正式版。
- 不执行未经授权的 reset、暂存区恢复或提交历史重写。
- 必要的新代码注释使用精准中文，不重复代码含义。
- 匹配和排序规则保持；大幅改规则必须另行展示前后对照并取得用户确认。

## 2. 当前实现与复用边界

| 现有入口 | 重写用途 |
|---|---|
| `src/QBox.Core` | 匹配、历史、排名、双 Ctrl 和界面状态的行为规格 |
| `src/QBox.Windows` | NTFS、索引、应用/快捷方式、身份及启动行为规格 |
| `src/QBox.Desktop` | 输入、窗口、热键、托盘、后台生命周期规格 |
| `src/QBox.Cli` | CLI 行为规格 |
| `rust/qbox-engine/src` | 复用并审查现有 Rust 匹配、拼音、排序与查询实现 |
| `tests/QBox.Checks` | 逐项迁移行为检查，不仅迁移样本文件 |
| `tools/QBox.EngineBench` | 冻结基线查询探针；不能以 Rust 混合模式作为唯一对照 |
| `tools/QBox.MemoryProbe` | 迁移确定性建库/增量/合并重放口径 |

以上均为相对仓库根目录的路径。现有 Rust 并不是完整 Rust 产品：建库、系统集成、历史持久化与桌面调用链仍有 C# 实现。部分 Rust 资源路径还引用 C# 源码目录中的拼音表与夹具，必须迁入 Rust 自有资源目录。

已有验证记录为 C# 685 组匹配、2950 项行为；Rust 对照为匹配 685、拼音 36、排序 2058。执行阶段 0 必须重新核对，这些是既有记录，不是本次文档任务的新实测。Rust 顶层 test 数量不能代替业务覆盖数量。

## 3. 目标架构

```text
Rust GUI / Rust CLI
          │
          ▼
      qbox-app ───────────────► qbox-platform
          │                    Windows / 后续 macOS
          ▼                          ▲
      qbox-engine ◄──────── Rust 索引工作进程
```

建议建立如下 workspace：

```text
rust/
  Cargo.toml
  Cargo.lock
  qbox-engine/          匹配、排序、索引读写、不可变快照与增量视图
  qbox-platform/        平台接口及 Windows 实现
  qbox-app/             查询调度、设置、历史、命令、后台生命周期
  qbox-desktop/         Rust 界面与桌面入口
  qbox-cli/             CLI 入口
  assets/              拼音表、图标及许可材料
  tests/fixtures/      冻结的行为样本
```

| 模块 | 职责与禁止事项 |
|---|---|
| engine | 纯数据和算法；不处理窗口、UAC、托盘或 Shell 启动 |
| platform | 系统能力；不决定排名、历史学习或搜索策略 |
| app | 编排与状态；不绘制控件，不建立第二套搜索实现 |
| desktop | 输入与展示；不在 UI 线程扫描索引或访问原始卷 |
| cli | 参数、输出与退出码；共用应用服务，不重写算法 |

GUI 使用普通权限。管理员索引进程仍然独立，但同样为 Rust，可由桌面 EXE 的 `--index-worker` 模式承载。工作进程只负责读取卷、构建/更新索引与发布状态，不额外准备一份仅供查询使用的预筛结构。

## 4. 技术选型与前置原型

首选 `egui/eframe`，优先验证 `wgpu` 图形后端；平台 API 通过 `windows` crate 集中封装；沿用 `serde` 与 `memmap2` 等已用能力。依赖须固定稳定版本、工具链和 Cargo.lock，不依赖上游主分支。新增依赖需记录用途、许可、体积与平台限制。

egui 提供 Rust 原生桌面路线、MIT/Apache-2.0 许可及可选原生无障碍支持。Slint 是备选，但须另行评估许可及分发条件。选型不是性能结论，不能凭框架宣传认定资源达标。

全面移植前，制作调用真实 Rust 搜索的 GUI 原型，并测试：

- 中文输入法组合输入、候选框定位、光标与选区、UTF-16 高亮到展示文字的映射。
- 中文字体、高 DPI、多屏切换、系统缩放和窗口定位。
- 双 Ctrl、托盘、激活与焦点恢复、失焦收起、Esc、关闭到托盘。
- 2000 条虚拟列表的滚动、选择、单击与 Enter 打开。
- 静止及隐藏时按需重绘，禁止无意义持续刷新。
- 界面自身 CPU、私有提交、工作集、峰值和 GPU 内存成本。

原型不满足关键输入或性能要求时，先定位并记录选型证据，再决定备选；不得带着已知问题展开全量 UI 移植。备选同样受纯 Rust 与性能约束，不能退回 C# 壳。

## 5. 搜索、并发与内存所有权

```text
输入 → 新查询版本 → 取消旧请求 → 持有不可变快照
     → Rust 搜索 → 核对查询/快照版本 → 展示当前结果
```

- 复用现有 Rust 核心，但审查其业务等价性，不重新设计排名。
- 每个查询拥有独立取消状态；移除依赖 C# SafeHandle 的裸指针取消生命周期。
- 查询通过 Arc 持有快照，执行期间不能释放映射；避免把映射数据伪装成无限生命周期引用。
- 结果携带查询与快照版本；旧查询、旧目录刷新或旧图标任务不得覆盖当前结果。
- 工作队列有界；连续输入不堆积完整扫描，取消检查覆盖预筛、扫描、排序与物化。
- 路径、字符串和图标按需物化，不为全部文件建立展示对象。
- 保留完整总命中统计及稳定平局次序；不得用提前截断伪造速度收益。
- 保持快捷列表上限 40、完整界面先 200 再续填至最多 2000 的现有行为。
- Windows 名称、路径与匹配保留原始 UTF-16，含补充字符与孤立代理项；有损展示转换不能改变身份、打开路径或持久化内容。
- 明确 Unicode 大小写、序号、历史时间和高亮坐标兼容规则，不能直接换成 Rust 默认字符串语义后认定等价。
- 图标、路径和派生索引缓存有预算与失效规则；快照切换、取消及反复显隐后资源不得持续增长。

## 6. 索引格式、增量与发布

采用只读基础快照、追加增量、单写者、按世代发布。首先保持数据语义等价，不同时引入新压缩或匹配规则。

```text
选合并检查点 → 写新基础 → 接入其后的增量
            → 校验/持久化 → 发布 manifest → 读端切换 → 回收旧世代
```

### 格式与读取

- Rust 实现完整持久化写入，不能把现有内存镜像构造器当作完整文件存储实现。
- 支持旧 v1/v2 读取与副本转换。新格式可采用 v3 对齐布局，但须独立验证。
- 明确端序、版本、计数、偏移、摘要范围与填充规则；填充纳入摘要和长度校验。
- 分配、切片、整数转换前检查边界与溢出；非零填充即使摘要正确也必须拒绝。
- 不复制整份基础文本来绕开对齐；映射文本直接借用，增量分配单列报告。
- unsafe 只保留在必要的系统与映射封装中，并说明地址对齐、边界和生命周期依据。

### 世代一致性

- 不原地修改已映射基础文件；通过小型 manifest 指向完整的新世代。
- 新基础和尾部增量完整持久化后才能发布，避免检查点空洞、重复应用或数据回退。
- 读端验证新世代后切换，失败继续使用上次有效视图；单卷失败不拖垮其他来源。
- 明确增量绑定身份；副本格式转换保留所需身份与检查点，不能静默重置日志。
- 合并期间继续接入更新；测试新增、删除、改名和父链变化不丢失。
- 旧查询持有旧世代；回收由所有权、读端生命周期和明确的跨进程策略约束。
- 清理失败不能阻塞发布，也不能无限积累；记录并执行磁盘预算与重试策略。
- 注入写入、flush、发布及重启边界故障，恢复只能选完整有效状态。

NTFS/USN 必须保留 FRN 序号、硬链接、DOS 别名、扩展记录、父目录移动、日志实例变化及断档处理。普通目录监听不能替代这些行为后宣称对等。

## 7. Windows 集成与桌面行为

| 项目 | 必须保持或实现 |
|---|---|
| 双 Ctrl | 不吞正常 Ctrl；隐藏时唤起快捷框，再次进入完整面板；继续遵循现有状态机 |
| 热键 | 统一配置、注册、注销与冲突提示；未实现的工具不抢占默认热键 |
| 单实例 | 按用户和状态目录区分；版本身份明确，不能误唤回旧程序后当作新版本测试 |
| 应用来源 | 快捷方式、打包应用、启动参数、工作目录、身份、目录刷新及失败保留 |
| 启动与学习 | 校验当前结果有效性；提交启动成功后才记历史，失败不学习 |
| 历史 | 查询关联、时间与身份规则；明确身份时迁移，硬链接歧义不猜测 |
| 图标 | 后台、有界、可取消；隐藏后可释放，旧任务不污染新列表 |
| 后台权限 | 普通 GUI 与管理员 worker 分离，拒绝授权不循环弹出 |
| 进程退出 | 正常退出、崩溃、取消与租约超时均能停止对应 worker |
| 设置与历史 | 原子发布、错误保留旧文件、可见日志与恢复行为 |

管理员通信只接受索引所需结构化命令，验证用户、任务身份及目标目录；校验通信长度与参数，不暴露任意命令执行接口。真实测试只操作本次新建的隔离文件，不破坏已有用户文件。

剪贴板、截图、翻译、桌面整理未来通过独立服务和统一命令接入。搜索服务不持有这些模块的私有状态；重型图像、OCR 或翻译资源按需加载，不能在启动搜索时全部初始化。

## 8. 数据迁移与 macOS 边界

### 数据迁移

首次试用使用独立目录，按副本执行：旧设置/历史解析 → Rust 读取旧索引与增量 → 转换 → 身份/名称/原始文本/检查点/结果对照 → 重启验证。失败保留原始副本；需要重建时使用 Rust worker。

不要求旧 C# 程序读取新格式。回退使用保留的旧程序和旧数据，而不是新程序嵌入 C#。正式迁移或替换另行评审。

### 平台边界

公共层不能假定盘符、反斜杠、NTFS FRN 或 UAC。定义文件发现/变更、文件身份、应用枚举/启动、热键/权限、菜单栏/托盘、窗口激活及图标接口。Windows 实现放在 cfg 隔离的平台模块内。

macOS 后续重新实现文件发现和恢复机制，不能复制 USN 假设；FSEvents 的事件合并、丢失后扫描与权限问题须单独设计。本次允许交付公共层跨平台编译验证，没有 macOS 实机证据不得声称支持完整 macOS 产品。

每阶段记录交付提交、实际命令输出、测试证据、未完成项和下一步。阶段 0 将原检查逐项登记为“原检查 → Rust 检查 → 必要实机证据”；不能仅以测试数量增加推断覆盖对等。

阶段 7 只有前面验收成立后才清理活动 C# 工程及其构建引用。先将夹具、拼音表和许可迁入 Rust 自有目录；保留 Git 历史与只读 release 档案。离线基线与新发布包严格分离。

## 10. 性能验收

### 对照对象与门槛

主基线是冻结 feat-new 默认 C# 产品路径，现有 Rust 混合路径仅作辅助对照。不得挑选较慢的混合路径作为唯一基线。

目标为各项搜索和整体性能不降级，不默认允许 5% 退化。阶段 0 先测同基线 A/A 噪声，冻结统计方法、复测批次和异常运行排除规则。报告点估计、置信区间与原始分布；可复现退化判失败，噪声不足以判定则标不确定并独立补测，不能把“不显著”直接解释成已证明无退化。未清零的不确定项不允许总体通过。

### 测量矩阵

| 项目 | 要求 |
|---|---|
| 核心查询 | static/live × 40/200/2000；首次与预热分开 |
| 查询集合 | 原七类 Any、800Q、.code、nd、Tra、chatgpt、rtt，加 1、CODE、python、豆包；补中文、拼音、混合、重复字符、无结果、宽泛查询 |
| 结果对照 | 总命中、ID、名称、目标、类型、分数、分组、顺序、高亮、历史信号及启动参数 |
| GUI | 首次唤起、隐藏后再唤起、输入到正确版本结果完成、2000 条续填及滚动 |
| 索引 | 初建、保存、加载、增量读/应用、追加、合并、重新映射 |
| CPU | 搜索 CPU 时间、静止/隐藏 CPU、无变化后台更新开销 |
| 内存 | 私有提交、工作集、峰值、派生缓存、GUI/worker 成本及 GPU 资源 |
| 稳定性 | 查询/取消/快照切换/显隐/worker 重启循环及长时运行 |

### 方法

- 同机、同电源模式、同索引逻辑内容、应用目录、历史与缓存策略；固定 Release 编译参数，测量时不并行构建。
- 至少 5 个新进程/组，A/B、B/A 交错；预热后每查询至少 10 次计时，逐项报告中位数、P95 与样本数。
- 首次、加载/准备、搜索、排序/物化和 UI 阶段分开；文件缓存未清除时不能称物理磁盘冷启动。
- 每轮逐项核对结果，不只比较最后一轮；不能只核对命中数或几个展示字段。
- 越线独立复测，保留初次失败；不反复挑选最好的一批，不用整体均值掩盖慢项。
- GUI 完成条件绑定本次查询版本与正确结果；固定 sleep、旧结果、仅有列表项均不能充当完成证据。
- 内存至少 3 轮，搜索完成且窗口显示、隐藏 2/12/20 秒分别采样；两组采用相同空闲回收策略，无额外强制回收。
- 窗口唤起至少 20 次；隐藏超过 10 秒后再唤起，标明测量端点，不能将 UI 自动化稳定等待冒充按键到像素。
- 真实 worker 开/关分别测；记录进程树与 GUI/worker 总 CPU、私有提交成本。共享映射工作集不能简单重复相加。
- 同时报告真实 RAM 与私有提交；低工作集不代表少分配，私有提交下降也不证明搜索更快。
- 迁移已有 201001 条记录、2000 条 USN 改名的确定性重放；它不能替代物理磁盘吞吐或真实卷恢复。
- 长时测试记录持续时长、轮数、资源曲线与残留进程，不以短循环宣称长期稳定；建议至少一次 8 小时运行。

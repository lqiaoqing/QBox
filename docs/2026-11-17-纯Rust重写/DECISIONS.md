# 决策与验证门槛

日期：2026-11-17。下列是补充设计决策，均未声称通过新产品实测。用户已确定的约束：纯 Rust、不保留 C# 架构、现有功能保持、性能与搜索速度不降级、不使用 leader 技能。

## ADR-01：复用算法，重建产品调用链

选择：在现有 qbox-engine 上重构所有权与持久化，GUI/CLI 直接调用 Rust API；移除产品 cdylib、ffi.rs 和 C# 回退。旧 C# 只冻结为开发对照。

理由：现有模糊匹配、拼音和排序已有对照样本；另写算法会增加行为风险。保留 C# 壳会延续重复准备和生命周期问题。代价：系统集成、历史与索引写入必须真实移植，不能只换壳。

## ADR-02：GUI 首选 eframe，选型须先过原型

选择：egui/eframe + wgpu，按需重绘，Windows 原生 API 封装热键/托盘/激活。Rust stable 和 Cargo.lock 固定依赖。版本号与 Windows 工具链在 T00/T01 实测锁定，不依据 latest 文档编造可用 API。

备选：Slint 需重新评估许可与资源；单独手写完整 Win32 控件层会增加维护工作；WebView 与 C# 界面不符合本次边界。不得以备选为理由绕过功能和性能门槛。

门槛：输入法、高 DPI、焦点、无障碍、隐藏 CPU/GPU、2000 行虚拟列表。失败先保留原型证据，再在本文记录具体选型修订；可继续不依赖 GUI 的核心任务，但不能宣布产品通过。

## ADR-03：直接 Rust 类型、每请求取消、不可变快照

选择：请求级 Arc<AtomicBool>、单查询执行槽+最新待执行槽、Arc<SnapshotSet>，显示结果拥有自己的可激活数据。索引更新、目录更新通过统一协调器发布 revision。

线程队列选择 std::thread + crossbeam-channel bounded/select；取消关闭专属唤醒通道使阻塞等待结束，避免只设标志但线程仍卡在满队列。暂不引入另一套异步调度运行时。

代价：必须明确续填和静默刷新语义；丢弃过时结果不能靠释放仍在执行的原生对象实现。UI 状态转换和协议见 DESIGN。

## ADR-04：世代文件与双 manifest 槽

选择：QBI v3 基础 + 新 QBD v2 二进制增量，世代 UUID，双 manifest 槽按提交序号发布，单写者；代际文件锁保护映射与回收。旧 v1/v2 QBI 与旧 QBD 仅作为导入输入。

理由：映射中的大文件不覆盖，减少原 ReplaceFile 并发问题；双槽给进程中断留下上一提交点。新 QBD 使用 UTF-16 单元，避免 JSON 实现对孤立代理项的差异。

代价：这是新增存储协议，不是仅加一字节填充；必须先过二进制、故障与代际并发测试。若此项成本不成立，应带证据修改 ADR，不能执行者暗中退回原地写文件。详细边界见 STORAGE。

## ADR-05：阻塞型 Windows 工作线程 + 受限命名管道

选择：专用消息循环线程处理热键与托盘；STA Shell 队列；索引 worker 每卷单写者；worker 为命名管道服务端，GUI 为客户端，双方核对真实进程身份。只交换控制和状态，不传搜索请求或全部索引。缓存 IO 使用父 GUI 的普通用户 impersonation token，原始卷读取另用提升权限线程。

理由：权限隔离保留，避免另一套引擎与 IPC 搜索成本。进程和任务身份互相验证，不能仅凭管道名称授权。安全协议见 WORKER-PROTOCOL。

## ADR-06：性能目标零退化，不能以噪声作通过依据

选择：冻结默认 C# 产品基线；先 A/A 校准；固定查询、样本和三次预定分析时点，按 VALIDATION 的同时区间判断。新增默认统计方法不来自旧实验，须反向验证。

代价：没有正的非劣效容差时，真实性能接近也可能判不确定。有限样本不能证明数学上的绝对相等；不确定是合法阻塞结果，不能伪造通过、事后调阈值或无限复测直到绿色。

## ADR-07：默认资源预算是初始实现参数

初始选择：图标缓存 16 MiB/512 项；路径缓存 8 MiB；搜索 1 执行+1 最新待执行；静默刷新合并通知；Shell 队列 64 项；进度通知每卷最多 4 次/秒。预算是**设计默认值，未实测**，不等同用户要求或性能验收阈值。

调整必须先记录原因与前后数据；不得让图标、路径、已完成快照队列无限增长。保持原有功能及性能标准，不用降低结果上限补偿资源问题。

## 与 PLAN 的关系及明确化

CLI 的 `--index` 保留逻辑入口，新建输出采用 locator+managed store，旧 QBI 只读兼容及显式导入。这样不再维护“GUI 用世代、CLI 用大文件覆盖”的两套恢复机制；代价是移动入口要包含 sidecar，旧 C# 不支持新输出。格式变化须在 CLI 兼容报告中列明，单文件交换使用导出 QBI v3。

- 保留八阶段总纲，拆成 T00–T18；阶段 2、3、5 增加性能准入，阶段 6 是综合复核。
- 将 manifest、IPC、取消和字符串的原则落到明确协议；这是新增设计，不是原文已包含的细节。
- 400 次保存及 8 小时稳定性来自上一版文档的实施补充；不宣称用户曾指定这两个数字。
- 本次明确 QBD v2 与旧 JSON 日志仅导入；旧产品不读取新写入格式，降级靠旧副本。

## 尚需验证的项目

| 门槛 | 所属任务 | 未过时的处理 |
|---|---|---|
| GUI/输入法/驱动资源 | T01、T14 | 不全面替换界面，不宣布产品性能通过 |
| 原始 UTF-16 的旧 JSON 导入 | T02、T08 | 保留旧日志；无法无损读取时标不支持该导入，不静默替换字符；先尝试无损解析，否则独立重建并验证 |
| 普通 token 的缓存 IO、目录句柄及 reparse 防护 | T09 | 不启动真实卷写入链；先完成身份/路径故障测试，不以提权线程直接写缓存 |
| NTFS/USN 实机 | T10 | 仅报告自动/重放结果，不当作实机支持 |
| 性能/置信区间不能排除退化 | T05、T11、T15 | 不确定且不合并替换；按固定补测上限结束 |
| 断电与磁盘硬件缓存 | T07 | 本轮必须测进程中断；突然断电保证单列，不能由进程 kill 推断 |
| macOS 实机 | 后续 | 不阻塞 Windows 交付，不声称完整 macOS 支持 |

实施遇到不同技术事实，在本文件追加决策变更、影响任务和失效证据；不得把未通过改写成已完成。

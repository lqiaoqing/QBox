# 0.2.3 内存优化续作

基线为 `a0a8d8c`（运行时代码为 0.2.2）。本次落实名称共享、低频 ASCII 预筛及无变化重查优化，并补充隐藏窗口的前台任务清理。匹配、排序、文件范围、USN 读取器、750 ms 后台轮询和租约心跳未调整。正式实例及正式索引未被本次测试替换。

## 与原方案的实际差异

全局完全去重原型确实少写了 **138.18 MiB**，且全部节点/名称/原始 UTF-16 等价，但几类宽查询的计时变差。本次没有采用该原型，也没有采用后来尝试的临时匹配缓存。

最终实现仅复用距离当前文本末尾不超过 **256 KiB** 的相同原始名称，保护候选遍历的局部性。这使实际收益收敛为 **26.59 MiB**，而不是把理论上限作为已实现收益。初建前 4,096 个名称完全不重复时停止持续建共享表；临时 USN 覆盖层直接顺序写文本，基础合并时再共享。

低频 ASCII 仅在稀疏编号载荷不超过位图八分之一时转换；高频英文、数字保留密集位图。稀疏交集用循环代替逐名称 LINQ 闭包。冻结快照的检索预处理存活托管数据减少 **9.80 MiB**。名称文件载荷与辅助结构的减少合计约 36.39 MiB，不能直接等同于 GUI 私有驻留下降同样数量。

## 实现与格式

- v2 仍直接读取 UTF-16 切片，名称记录、父目录、FRN、命名空间、属性和遍历顺序独立保留；不折叠大小写、不归一化 Unicode、不合并硬链接。重复文本允许有多个片段，以限制远距离回指。
- v1 按原连续文本路径验证、直接映射读取。v2 验证每次首次引用按序铺满文本、后续引用必须落在完整已有片段，保留父链、非法分量、物理编号和摘要校验。转换保留创建时间、卷及检查点，已有增量日志身份不变；旧查询继续持有旧映射。
- 减少 Create 中一次冗余物理编号 HashSet；完整发布前物理编号排序校验仍保留。没有实施全量 Synchronize 的大规模顺序合并改造。
- 纯检查点推进共享检索内容标识，更新视图/游标但不重查或迁移历史。快捷方式和系统应用目录比较完整内容，相同时复用已有预处理；快捷方式的参数、工作目录、标志及别名都参与判断。
- 隐藏时取消前台查询、清空结果行及过期图标队列；再次显示时从最新索引和历史重查。后台监测、目录刷新、USN 与更新心跳继续运行。图标任务按批次失效，已进入 Shell 的调用只丢弃过期回调，不强行中断 COM。

## 格式生效与兼容

0.2.3 可以直接使用原 v1 索引；**已有 v1 不会因打开窗口而自动改写**。名称共享随下一次正常新建/基础合并生效，旧索引上也能立即使用稀疏预筛和前台生命周期优化。开发探针的 `--pack` 只转换独立副本，不代替正式 NTFS 追赶。

0.2.2 不能读取 v2；需要降级时保留原 v1 副本或在旧版重建索引。历史和设置格式未变。本次保留 0.2.2 归档，未写正式历史或索引。

独立进程的完整来源内存探针在同样显式 GC 条件下，查询结束托管存活约 95.8 → 86.0 MiB，私有提交约 140.9 → 126.7 MiB；这些不是完整 GUI 的自然驻留承诺，产品不调用强制 GC 或工作集裁剪。

屏幕外 STA 窗口探针通过：隐藏输入/刷新不搜索、显示使用最新覆盖层、目录相同保留行对象、清空旧图标后仍可使用。重复显示后的查询回填约 26～42 ms；探针用占位图标且未进入正式 App Startup，不代表物理输入法、热键、完整绘制或端到端唤起延迟。

# 0.2.2 内存优化

基线为 `3f7713f` / 产品 0.2.1。用户要求改善工具常驻内存，并明确不能降低原有索引速度。本次未研究或修改 Listary 排名，不依赖其二进制或接口。

## 原因与改动

- GUI 和管理员后台原本分别把完整节点、名称、UTF-16 文本复制到托管堆，载入还会创建大字符副本和校验集合。现在映射同一只读 v1 文件，保留校验与原子替换；查询和结果持有其所有者，旧查询可继续读取旧快照。
- 存在目录增量时，原实现为大量普通候选提前生成完整路径，并缓存整棵目录树的路径字符串。现在先校验目录可达性，只在 EXE 判定或结果展示时生成路径，字符串缓存限额为 8,192 条。
- 应用目录此前用无限结果队列执行 `.lnk` 模糊查询，再丢弃绝大部分结果。现在流式读取实际快捷方式，保留原有身份、名称选择与动作合并规则。
- 固定节点/名称布局与 v1 磁盘字节一致，按块写出，减少逐字段及逐字符调用；初建、恢复和合并后转回映射，避免工作进程长期持有构建数组。

## 验证

685/685 匹配检查、2904/2904 行为检查通过，Release 零警告、零错误。新增检查覆盖原子替换时旧查询存活、GC 与句柄释放、非法边界与取消、UTF-16 字节往返，以及目录可达缓存在删除和恢复后的隔离。

同一份 2,920,457 文件、4,754,894 名称的基础快照，另含冻结增量及相同应用来源、空历史，22 组查询的总命中数和全部 SearchHit 字段摘要完全相同，包含原七类查询、拼音、中文、符号和 Unicode 边界。原始数值见 [对照数据](validation/memory-validation-2026-11-15.json)。

| 完整来源探针阶段 | 0.2.1 私有内存 | 0.2.2 私有内存 |
|---|---:|---:|
| 应用目录准备完成 | 976.3 MiB | 109.2 MiB |
| 22 组查询结束 | 1015.4 MiB | 140.0 MiB |

查询结束的托管存活数据由约 725.4 MiB 降至 95.8 MiB，应用目录准备由约 2125 ms 降至 463 ms。探针为了可比性显式 GC；这些数字不是完整 GUI 的自然驻留承诺。工作集包含文件映射的共享页，不能把多个进程的工作集直接相加当作独占物理内存。没有通过裁剪工作集、强制回收产品进程、减少文件或截断命中降低指标。

## 索引速度保护

相同的 201,001 条记录与 2,000 条改名输入重放到真实建库、增量、保存及合并代码。后四轮中位数如下；候选版保存和合并已包含额外重新映射成本。

| 阶段 | 0.2.1 | 0.2.2 |
|---|---:|---:|
| Build | 481.18 ms | 329.10 ms |
| Save | 77.58 ms | 66.09 ms |
| Load | 89.63 ms | 21.45 ms |
| 2000 条 USN 读取与应用 | 7.71 ms | 7.13 ms |
| 增量日志追加 | 6.36 ms | 5.74 ms |
| Synchronize、保存及切换视图 | 452.12 ms | 246.35 ms |

重放未观察到索引阶段退化。原始 MFT 读取器、USN 轮询间隔、来源覆盖和匹配排序未变；没有把 RAM 设备的缓存枚举重放冒充物理整盘扫描吞吐。不同磁盘与持续写入负载仍需各自验收。查询时间逐组保留，部分查询有波动，不能据此保证每个关键词都更快。

新旧写出的相同逻辑快照在去除创建时间和对应校验值后字节一致，旧 CLI 可读取新文件。无需索引迁移或重建，不覆盖用户历史、设置及旧版本归档。

本次构建为 0.2.2；正式 0.2.1 实例未被替换。窗口验收使用独立状态目录与索引副本，关闭自动更新，未强制 GC；`nd` 与中文查询后自然私有内存观察约 246～283 MiB，最终工作集约 805 MiB，其中包含文件映射的共享页。AX 状态已核对中英文结果，测试实例已结束；坐标输入不可用，因此不把物理输入法、完整点击流程或长期驻留列为已验收。

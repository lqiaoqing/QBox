# QBox 0.1.1 搜索检查

用户已经实测双击 Ctrl 可正常唤起，本轮不再重复唤起操作。继续处理普通排序、快捷方式动作合并和查询开销。没有采集 Listary 性能数据，没有修改其程序、配置或历史。

## 排序证据与实现范围

Listary 7.1.0.47 的 SHA-256 仍为 `f728593f86597b95d9ee79c03f8e7d313ca4c79a4bab8cf31f3768febeb8063f`。在原有只读 Ghidra 工程中定点反编译元数据构造器，追加原始比较指令模拟，未启动目标程序。

- `0x1415e2700` 按特殊标志、精确历史、前缀历史/具有非空身份的优先入口、强分数桶、混合桶前十、弱分数桶、混合桶余项合并。
- `0x14160ce60` 比较分数及可选最后访问时间；`0x14160d040` 比较来源键或按种类和分数构造的 64 位键，再比较可选最后访问时间。相等时保留输入顺序。
- `0x14062a730`、`0x140631c60`、`0x140631f20` 分别产生种类 1/2/3，第二类具有强弱分数分桶标志，第三类具有优先入口标志和可选字符串身份。动作构造链支持文件、目录、快捷方式的对应关系，但完整来源语义尚未恢复。
- `QBoxReplayOrdering.java` 对两类比较器各执行 1,024 组原始指令样本；仅模拟内存复制。2,048 组全部完成，并进入 `tests/QBox.Checks/Fixtures/launcher-ordering.json`。这只证明所选比较器及输入字段的比较行为，不证明完整 Launcher 等价。

QBox 已去掉先前按快捷方式 2、目录 1、文件 0 无条件提权的规则，改为共享的分桶与比较实现。完整排序和有界收集器保持一致，历史桶只按关联时间比较，同时间保留来源顺序。每桶只保留仍可能展示的条数；总匹配数仍完整累计。

Windows 来源尚不能提供原程序的全部非零来源键，当前使用默认键。特殊标志入口、完整来源过滤和元数据语义尚未接齐。QBox 的应用来源先按最佳别名分数排列，这不是已经证明等价的 Listary 来源顺序。低相关应用仍可能靠前，因此不能把本版称为完整还原的普通排序。

## 快捷方式动作合并

读取当前用户及公共开始菜单、桌面中已索引的 `.lnk`。在独立 STA 线程只读加载并读取保存字段，不调用 Resolve，不启动目标。链接本身先核对卷与文件身份。

仅当目标、参数、工作目录、窗口状态、所有链接标志均完全相同时合并。比较保留大小写，宁可少合并，也不把不同启动动作误并。全部别名仍参与匹配，任一别名的历史均可提升合并动作；实际打开主快捷方式，保留其启动语义。CLI 同样支持通过别名搜索后打开主 ID。

真实快照读取出 231 个可解析入口、222 个动作。虚拟/UWP 目标、不可读、丢失或疑似截断字段不参与合并，保留原文件入口。显式 `.lnk` 查询显示全部原始路径；只有扩展名片段命中的查询也保留原文件。开始菜单/桌面以外的文件路径没有被删去。

接口依据为 Microsoft 的 [IShellLinkW](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ishelllinkw)、[GetPath](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllinka-getpath)、[GetArguments](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishelllinkw-getarguments) 和 [IPersistFile.Load](https://learn.microsoft.com/en-us/windows/win32/api/objidl/nf-objidl-ipersistfile-load)。

## 名称预筛选

载入后建立 ASCII 字符存在位图，使用与匹配器相同的 Rune 大写转换。查询取字符交集后仍逐项执行完整有序匹配；重复字符和字符顺序不由位图代替判断。DOS 短名命中转交到长名入口，Unicode 查询完整回退，取消构建不缓存半成品。查询位图使用池化数组，不写入原始卷或快照格式。

自动检查覆盖 ASCII/Unicode 大小写、无点 i/长 s、重复字符、缺失字符、DOS 别名、多卷、历史、不同显示条数，以及较早分组在遍历中增加后对较晚分组的安全裁剪。普通排序和预筛选均与完整候选排序对照。

## 真实盘结果

使用原有 C/D 快照，共 3,005,514 条文件/目录记录。以下为独立检查程序的查询核心样本，不包含 UI 与图标，不是稳定性能承诺。首次快照载入约 1.9 秒，位图准备约 0.5 秒。

| 查询 | 预热后核心时间 | 用户目标的无关联历史排名 | 隔离内存中记录一次选择后 |
|---|---:|---:|---:|
| Any | 约 45 ms | 63 | 1 |
| 800Q | 约 3–4 ms | 1 | 1 |
| .code | 约 42–44 ms | 11 | 1 |
| nd | 约 63–67 ms | 1 | 1 |
| Tra | 约 64–68 ms | 1 | 1 |

五个目标均覆盖；模拟选择记录后以大写查询检查，五项均为首位。这里直接调用隔离的内存历史记录，不代表用户已经在新窗口中完成五次打开，也没有导入或预填用户历史。前九项中另一处同名 `.codex` 不等于用户指定的 `%USERPROFILE%\.codex`，表格使用完整目标路径判断。

验证命令为 `scripts/verify.ps1`：685 组匹配分值对照、2,727 项行为/格式检查全部通过，Release 无警告、无错误。行为数量包含上述 2,048 组排序对照。检查输出在 `work/verify-final-20261114.log`，真实查询与学习回归在 `work/desktop-engine-check/results-final-20261114.log`。
